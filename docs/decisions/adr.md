# ADR

## ADR-001: 가격 예측보다 시장 설명을 우선한다

- **상태**: Accepted
- **결정**: 미래 가격 산출을 제품 계약에서 제외한다.
- **근거**: 현재 데이터는 시장 상태와 외부 사건을 설명하는 데 더 적합하다. 정확한 미래 가격은 불필요한 모델 위험을 추가한다.
- **결과**: 모든 화면은 관측, 상대 비교, 과거 context에 집중한다.

## ADR-002: 대표 선수 기반 PoC를 사용한다

- **상태**: Accepted
- **결정**: 20~30명의 인기 선수를 seed하고 주요 클래스와 강화단계만 수집한다.
- **근거**: 전체 시장 수집 전에 분석 구조와 데이터 접근성을 검증할 수 있다.

## ADR-003: 가격은 `spid + grade` 단위로 관리한다

- **상태**: Accepted
- **결정**: 실존 선수와 클래스 카드, 강화단계 시장 자산을 분리한다.
- **근거**: 같은 클래스도 강화단계별 가격과 거래 특성이 크게 다르다.

## ADR-004: 대체관계를 first-class data로 저장한다

- **상태**: Accepted
- **결정**: 카드 간 관계를 별도 table로 보존한다.
- **근거**: 공급 충격은 직접 포함 카드 외의 대체재로 전파될 수 있다.

## ADR-005: 설명 가능한 통계를 사용한다

- **상태**: Accepted
- **결정**: 중앙값, 상대강도, breadth, IQR·MAD부터 사용한다.
- **근거**: 분석 결과를 개발자 본인이 검증하고 설명할 수 있어야 한다.

## ADR-006: Market Index는 중앙 수익률 기반으로 시작한다

- **상태**: Accepted
- **결정**: 가격 자체를 평균내지 않고 카드별 수익률의 중앙값을 누적한다.
- **근거**: 카드별 유통량을 알 수 없어 시가총액 가중치를 만들 수 없다.

## ADR-007: 실사용성은 행동 데이터로 보조한다

- **상태**: Accepted
- **결정**: 랭커 사용량과 경기 통계를 사용한다.
- **근거**: 세부 능력치만으로 체감, AI 움직임, 팀컬러 적합성을 완전히 표현하기 어렵다.

## ADR-008: 공지와 적용 시간을 분리한다

- **상태**: Accepted
- **결정**: `announced_at`과 `effective_at`을 별도로 저장한다.
- **근거**: 시장은 실제 패치 이전에 정보를 선반영할 수 있다.

## ADR-009: Shock를 정상 시장 모델과 분리한다

- **상태**: Accepted
- **결정**: 이상 움직임을 먼저 탐지하고 원인은 나중에 연결할 수 있게 한다.
- **근거**: SSS와 같은 운영사 사고는 사전 변수로 정의할 수 없다.

## ADR-010: 시장 규칙 변경을 regime marker로 저장한다

- **상태**: Accepted
- **결정**: 기준가 산정 규칙 등 가격 형성 방식의 변경을 데이터에 남긴다.
- **근거**: 동일한 가격 시계열이라도 생성 메커니즘이 달라질 수 있다.

## ADR-011: 자동 크롤러보다 데이터 이용 가능성 검증을 먼저 한다

- **상태**: Accepted
- **결정**: 비공식 DataCenter endpoint를 자동 수집 경로로 기본 채택하지 않는다.
- **근거**: NEXON Open API 약관에는 허가되지 않은 자동 스크래핑·크롤링 제한 조항이 있다.

## ADR-012: 원본과 파생 데이터를 분리한다

- **상태**: Accepted
- **결정**: raw snapshot은 변경하지 않고 derived table을 다시 생성한다.
- **근거**: 계산 방법 변경 시 과거 데이터를 재수집하지 않고 재분석할 수 있다.

## ADR-013: 이벤트 annotation은 초기에는 사람이 한다

- **상태**: Accepted
- **결정**: 공지 자동 자연어 분석을 PoC 범위에서 제외한다.
- **근거**: 수십 개 핵심 사건은 수동 입력 비용이 낮고 잘못된 자동 분류를 피할 수 있다.
