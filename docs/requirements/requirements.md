# 요구사항 정의서

요구사항의 핵심은 모든 분석 결과가 원본 데이터까지 추적 가능해야 한다는 점이다.

## 기능 요구사항

- 대표 인기 선수의 선수 identity를 관리한다
- 동일 선수의 여러 클래스와 강화 단계를 별도 시장 자산으로 관리한다
- 선택한 카드의 최대 365일 가격 시계열을 저장한다
- 가격 원본의 timestamp와 원본 값을 수정 없이 보존한다
- 선수의 OVR, 급여, 포지션, 세부 능력치, 특성을 저장한다
- 선수와 소속팀·국가·팀컬러 관계를 저장한다
- 상위 랭커 사용량과 실사용 기록을 가능한 범위에서 저장한다
- 동일 선수의 다른 클래스를 직접 대체관계로 연결한다
- 동일 포지션·팀컬러·급여·성능 구간의 후보를 대체재로 연결한다
- 공지, 업데이트, 이벤트, 상품, 멤버십, 시장 정책 변경을 시간축에 기록한다
- 이벤트의 공지 시각과 실제 적용 시각을 분리한다
- 유료상품의 판매 시작·종료, 가격, 구매 제한, 구성품을 기록한다
- 선수팩의 클래스, 강화 범위, Top Price 범위, OVR 조건 등을 구조화한다
- BP 공급과 선수 공급을 별도 변수로 취급한다
- 상품·이벤트에 직접 포함된 선수군을 `direct exposure`로 표시한다
- 직접 노출 카드의 대체재를 `indirect exposure`로 연결한다
- 전체 시장과 선수군별 지수를 계산한다
- 선수군의 시장 대비 상대강도를 계산한다
- 시장 상승 종목 비율을 계산한다
- 선수군 간 가격 분산 변화를 계산한다
- 평상시 범위를 벗어난 움직임을 이상징후로 표시한다
- 시장 구조 변경 시점을 별도 regime으로 기록할 수 있다
- 과거 이벤트 전후 시장 반응을 재생할 수 있다
- 모든 파생값에서 사용한 원본과 계산 버전을 추적할 수 있다
- 이벤트에 사람이 메모와 분류를 추가할 수 있다
- 데이터가 부족한 지표는 결과 없음으로 처리한다
- 상관관계를 인과관계로 표시하지 않는다
- 가격 데이터와 실제 체결 데이터를 동일한 개념으로 표시하지 않는다

## 비기능 요구사항

PoC는 정확한 재현과 설명 가능성을 우선한다.

- 동일한 원본에 같은 분석 버전을 실행하면 같은 결과가 나와야 한다
- 원본 데이터는 파생값과 분리해 보존한다
- 모든 시간은 원본 timezone을 보존하고 분석 기준은 KST로 통일한다
- 소스가 변경돼도 기존 원본 데이터는 다시 분석할 수 있어야 한다
- 수집 실패를 0 또는 가격 미변동으로 해석하지 않는다
- 누락값과 실제 0을 구분한다
- 데이터 수집 조건과 이용약관을 우회하지 않는다
- 출처가 불분명한 제3자 데이터를 핵심 기준값으로 사용하지 않는다
- Python을 필수 런타임으로 만들지 않는다
- 생성형 AI 호출이 없어도 핵심 분석을 수행할 수 있어야 한다
